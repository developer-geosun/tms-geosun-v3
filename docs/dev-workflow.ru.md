# Алгоритм разработки TMS GeoSun

**Дата создания:** 17 сентября 2026, 13:56 (UTC+3)  
**Дата изменения:** 17 сентября 2026, 14:32 (UTC+3)

Канон процесса после фиксации baseline. Клиент: **Angular + Java**. Flutter вне процесса (заморозка).

Связанные документы:

- Реестр: [`docs/specs/README.ru.md`](specs/README.ru.md)
- Baseline: [`docs/specs/BASELINE.ru.md`](specs/BASELINE.ru.md)
- Архитектура (DDD): [`docs/architecture/ddd-pragmatic.ru.md`](architecture/ddd-pragmatic.ru.md)
- Архив (не источник истины): [`docs/archive/README.ru.md`](archive/README.ru.md)

Между воротами — стоп, пока нет явного «+» (или «можно дальше») от владельца задачи.

## Выбор алгоритма

| Ситуация | Алгоритм |
|----------|----------|
| Новая тема, явный бэклог, фича вне канона | **A** — новая разработка |
| Изменение уже `реализовано` / `в силе` / строки канона в BASELINE | **B** — доработка реализованного |
| Баг: код не совпадает со спекой | короткий change-brief → узкий план → fix (спеку не раздувать) |
| Баг: спека ошибочна, код «как написано» | **B** (правка спеки + код при необходимости) |
| Мелочь (опечатка i18n, комментарий; контракт не меняется) | сжато в одном сообщении; спеку не трогать |

```
Задача → A (новое) или B (доработка)
```

## DDD при исполнении (A4 / B4)

С **17 сентября 2026** действует [`docs/architecture/ddd-pragmatic.ru.md`](architecture/ddd-pragmatic.ru.md):

- **Core** (маршруты, фрахт/quote/ставка, рейсы): в плане и коде — use case → агрегат/правила → порт; не импортировать чужие JPA-сущности.
- **CRUD / Identity / Storage / Notification:** transaction script достаточно.
- Полный рефакторинг «под DDD» — только отдельной задачей **B**, не «заодно» с фичей.
- Angular не дублирует доменный FSM/формулы.

## Алгоритм A — новая разработка

Ворота: **brief → новая спека → план → исполнение**.

### A1. Business brief

Шаблон: [`docs/templates/business-brief.ru.md`](templates/business-brief.ru.md).

Фиксирует зачем и для кого: проблема, роли, ценность, сценарий успеха, out of scope. Без API и пакетов.

**Выход:** brief принят («+»).

### A2. Спецификация

1. Открыть [`docs/specs/README.ru.md`](specs/README.ru.md) и [`BASELINE.ru.md`](specs/BASELINE.ru.md) — нет ли уже темы.
2. Скопировать [`docs/templates/specs/_template.ru.en.md`](templates/specs/_template.ru.en.md) → `docs/specs/<feature>.<lang>[.<lang>…].md`.
3. Заполнить Scope / Out of Scope / API / DoD / блок **Статус**.
4. Добавить строку в реестр.

**Выход:** спека принята («+»). На этом этапе не писать production-код.

### A3. План

Промпт: [`docs/templates/prompts/spec-to-plan.en.ru.md`](templates/prompts/spec-to-plan.en.ru.md).

План: понимание, шаги, файлы, риски, приёмка, **отдельный** пункт Problems = 0 (включая Java-тесты).

**Выход:** план принят («+»). План ≠ код.

### A4. Исполнение

Промпт: [`docs/templates/prompts/feature-implementation.en.md`](templates/prompts/feature-implementation.en.md).

Ветка `feature/…`, шаги плана, lint/Spotless/тесты, Problems = 0. Обновить Статус, реестр, DoD; при необходимости BASELINE или Бэклог.

## Алгоритм B — доработка реализованного

Ворота: **change-brief → правка существующей спеки → дельта-план → исполнение**.

Без второй «параллельной» спеки на ту же тему.

### B1. Change-brief

Шаблон: [`docs/templates/change-brief.ru.md`](templates/change-brief.ru.md).

Что меняем, зачем, текущее vs желаемое, что не трогаем, ссылка на канон-спеку из BASELINE/README.

**Выход:** change-brief принят («+»).

### B2. Правка спеки

Открыть реестр → канон-файл → «Связанные». Приоритет ролей: `источник истины` > `дополнение` > `исторический MVP` (архив не править как канон).

Внести дельту в Scope / API / DoD; в шапке — дата и кратко «изменение». **Не** создавать новый файл-дубликат на ту же тему.

Если доработка ломает границу baseline (новая подсистема) — переключить на **A**, в старой спеке сузить scope и сослаться на новую.

**Выход:** правка спеки принята («+»).

### B3. Дельта-план

Тот же `spec-to-plan`, scope = diff: только затронутые модули, риски регрессии, Problems = 0.

**Выход:** план принят («+»).

### B4. Исполнение и закрытие

Код по дельта-плану без расползания в соседние домены. Обновить Остаток/DoD; если сдвинули границу канона или закрыли кусок бэклога — строки в BASELINE и README.

## Запреты

- Brief ≠ спека (в brief нет эндпоинтов).
- Спека ≠ план (спека — *что*; план — *как по файлам*).
- План ≠ код (пока нет «+» на план — не реализовывать).
- Не читать все спеки подряд: BASELINE/README → один файл → связанные.
- Не брать seed UUID `c1000000-…` (актуально: UA V39, `c2000000-…`).
- Исторический MVP и файлы в `docs/archive/` — не источник истины для новой разработки.
